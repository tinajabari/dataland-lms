# سیستم مدیریت یادگیری (LMS) — دیتالند

پروژه‌ی پایانی درس پایتون، ساخته‌شده با **Django** و **Bootstrap 5 (RTL)**.
یک LMS ساده ولی کامل که در آن مدیر، مدرس و دانشجو هرکدام دسترسی و امکانات مخصوص خودشان را دارند.

## اپلیکیشن‌ها

| اپ | مسئولیت |
|---|---|
| `accounts` | ثبت‌نام/ورود، پروفایل، **نقش‌ها** (مدیر/مدرس/دانشجو)، مدیریت کاربران |
| `courses` | دوره‌ها، درس‌ها، ثبت‌نام دانشجوها، مدرس‌ها، فرم «مشاوره رایگان» |
| `blog` | وبلاگ آموزشی (اضافه بر نیازمندی‌ها) |

---

## ۱. نگاشت نیازمندی‌ها به پیاده‌سازی

### ۱) مدیریت کاربران و نقش‌ها

| نیازمندی | پیاده‌سازی | آدرس / فایل |
|---|---|---|
| ثبت‌نام کاربران | فرم ثبت‌نام (انتخاب نقش دانشجو یا مدرس) | `/accounts/signup/` |
| ورود / خروج | ورود با `django.contrib.auth`؛ خروج با فرم POST | `/accounts/login/` |
| مدیریت اطلاعات کاربران | کاربر اطلاعات خودش را ویرایش می‌کند؛ **مدیر** همه‌ی کاربران را جستجو، ویرایش، فعال/غیرفعال و نقش‌شان را عوض می‌کند | `/accounts/profile/` ، `/accounts/users/` |
| تعریف نقش‌های مدیر، مدرس، دانشجو | مدل `accounts.Profile` با فیلد `role` | `accounts/models.py` |
| دسترسی متناسب با نقش | دکوراتور `role_required` + تابع `can_manage_course` + منوی نقش‌محور | `accounts/roles.py` |

### ۲) مدیریت دوره‌ها

| نیازمندی | آدرس |
|---|---|
| ایجاد دوره جدید | `/courses/new/` (مدرس و مدیر) |
| مشاهده فهرست دوره‌ها (جستجو + دسته‌بندی) | `/courses/` |
| مشاهده جزئیات دوره | `/courses/<slug>/` |
| ویرایش اطلاعات دوره | `/courses/<slug>/edit/` (فقط مدرسِ همان دوره یا مدیر) |
| حذف دوره (با صفحه‌ی تایید) | `/courses/<slug>/delete/` |
| غیرفعال/فعال کردن دوره | دکمه‌ی «غیرفعال کردن» در صفحه‌ی دوره یا پنل مدیریت (دوره‌ی غیرفعال برای دانشجو نامرئی است ولی داده‌ها حفظ می‌شوند) |
| اختصاص مدرس به دوره | مدرس: خودکار به خودش. **مدیر:** فیلد «استاد» در فرم دوره |
| پنل مدیریت دوره‌ها | `/courses/manage/` (مدرس فقط دوره‌های خودش؛ مدیر همه) |

### ۳) مدیریت درس‌ها و محتوا

| نیازمندی | پیاده‌سازی |
|---|---|
| ایجاد درس برای یک دوره | `/courses/<slug>/lessons/new/` |
| عنوان و توضیحات درس | فیلدهای `title` و `description` |
| محتوای آموزشی **یا** آدرس آن | فیلدهای `content` (متن) و `content_url` — حداقل یکی الزامی است؛ اگر آدرس فایل ویدیویی (`.mp4`…) باشد پخش‌کننده نمایش داده می‌شود |
| ترتیب نمایش درس‌ها | فیلد `order` (فرم به‌طور پیش‌فرض شماره‌ی بعدی را پیشنهاد می‌دهد) |
| فهرست درس‌های هر دوره | بخش «سرفصل‌ها» در صفحه‌ی دوره |
| ویرایش و حذف درس | `/courses/lessons/<id>/edit/` و `/courses/lessons/<id>/delete/` |
| *(اضافه)* کنترل دسترسی به محتوا | محتوای درس فقط برای مدرسِ دوره، مدیر و **دانشجوی ثبت‌نام‌شده** باز می‌شود؛ بقیه فقط عنوان‌ها را می‌بینند |

### ۴) ثبت‌نام دانشجوها

| نیازمندی | پیاده‌سازی |
|---|---|
| مشاهده‌ی دوره‌های قابل ثبت‌نام | `/courses/` (فقط دوره‌های فعال) + نمایش «ظرفیت باقی‌مانده / تکمیل» |
| ثبت‌نام در یک دوره | دکمه‌ی «ثبت‌نام» (POST، فقط نقش دانشجو، بررسی ظرفیت) |
| دوره‌های ثبت‌نام‌شده‌ی هر دانشجو | `/courses/my-courses/` |
| فهرست دانشجوهای هر دوره | `/courses/<slug>/students/` (مدرسِ دوره و مدیر) |
| جلوگیری از ثبت‌نام تکراری | محدودیت `unique_together(student, course)` در دیتابیس + بررسی در ویو (حتی با دو کلیک هم‌زمان) |
| لغو ثبت‌نام «در صورت مجاز بودن» | دانشجو **تا قبل از شروع دوره** می‌تواند لغو کند (مدل: `Enrollment.can_cancel`)؛ مدرسِ دوره/مدیر در هر زمان. بعد از لغو، دانشجو می‌تواند دوباره ثبت‌نام کند (همان رکورد فعال می‌شود) |

## ۲. ماتریس دسترسی نقش‌ها

| امکان | مهمان | دانشجو | مدرس | مدیر |
|---|:-:|:-:|:-:|:-:|
| دیدن دوره‌های فعال و جزئیات | ✅ | ✅ | ✅ | ✅ |
| دیدن دوره‌های **غیرفعال** | ❌ | ❌ | فقط مال خودش | ✅ |
| ثبت‌نام / لغو ثبت‌نام خودش | ❌ | ✅ | ❌ | ❌ |
| دیدن محتوای درس‌ها | ❌ | فقط دوره‌های ثبت‌نام‌شده | دوره‌های خودش | ✅ |
| ایجاد دوره | ❌ | ❌ | ✅ (به خودش اختصاص می‌یابد) | ✅ (مدرس را انتخاب می‌کند) |
| ویرایش / حذف / غیرفعال‌سازی دوره | ❌ | ❌ | فقط دوره‌های خودش | همه |
| افزودن / ویرایش / حذف درس | ❌ | ❌ | دوره‌های خودش | همه |
| دیدن لیست دانشجوهای دوره و لغو ثبت‌نام آن‌ها | ❌ | ❌ | دوره‌های خودش | همه |
| مدیریت کاربران (نقش، فعال/غیرفعال) | ❌ | ❌ | ❌ | ✅ |

> دسترسی غیرمجاز: کاربر لاگین‌نکرده به صفحه‌ی ورود هدایت می‌شود و کاربر بدون دسترسی صفحه‌ی **۴۰۳** می‌بیند.
> مدیر نمی‌تواند حساب خودش را غیرفعال کند یا نقش خودش را عوض کند.

## ۳. مدل داده

```
User (django) ──1:1── Profile(role: admin|instructor|student, phone)
User ──1:1── Instructor ──1:N── Course ──1:N── Lesson(order, content, content_url)
User ──1:1── Student ──1:N── Enrollment(status) ──N:1── Course     [unique: student+course]
Course ──N:1── Category
```

وضعیت‌های ثبت‌نام: `approved` (فعال) · `pending` · `rejected` · `cancelled`.
ثبت‌نام دانشجو بلافاصله فعال می‌شود (`approved`)؛ مدیر می‌تواند از پنل ادمین جنگو وضعیت را تغییر دهد.
ظرفیت دوره فقط ثبت‌نام‌های `approved` را می‌شمارد، پس با لغو ثبت‌نام ظرفیت آزاد می‌شود.

## ۴. راه‌اندازی

```powershell
cd new_project
python -m venv .venv
.\.venv\Scripts\activate          # لینوکس/مک: source .venv/bin/activate
pip install -r requirements.txt

python manage.py migrate
python manage.py seed_demo        # (اختیاری) داده‌ی نمایشی برای دمو
python manage.py runserver
```

سایت: http://127.0.0.1:8000/ — پنل ادمین جنگو: http://127.0.0.1:8000/admin/

### حساب‌های نمایشی (بعد از `seed_demo`)

| نقش | نام کاربری | رمز |
|---|---|---|
| مدیر | `admin` | `Admin@12345` |
| مدرس | `teacher1` ، `teacher2` | `Demo@12345` |
| دانشجو | `student1` ، `student2` ، `student3` | `Demo@12345` |

داده‌ی نمایشی عمداً شامل این حالت‌هاست: دوره‌ی **تکمیل‌ظرفیت**، دوره‌ی **شروع‌شده** (لغو ثبت‌نام ممنوع)،
دوره‌ی **غیرفعال**، درس با متن و درس با آدرس (لینک).

> اگر قبلاً با `createsuperuser` کاربر ساخته‌اید، `migrate` برای کاربران قبلی خودکار «پروفایل نقش» می‌سازد
> (سوپریوزرها مدیر می‌شوند، کاربرانِ دارای پروفایل مدرس → مدرس، بقیه → دانشجو).

## ۴-ب. اتصال به Microsoft SQL Server

پروژه به‌طور پیش‌فرض از SQLite استفاده می‌کند. برای کار با SQL Server (مثلاً دیتابیس `Semtec_LMS`) این مراحل را انجام دهید.

**۱) ریستور بک‌آپ در SSMS:** روی `Databases` راست‌کلیک ← `Restore Database…` ← `Device` ← دکمه‌ی `…` ← `Add` ← فایل `Semtec_LMS.bak` ← `OK`.
اگر خطای دسترسی (Access denied) گرفتید، فایل `.bak` را در پوشه‌ی `Backup` خود SQL Server کپی کنید (مثلاً
`C:\Program Files\Microsoft SQL Server\MSSQL17.MSSQLSERVER\MSSQL\Backup`) و از همان‌جا ریستور کنید.
(بک‌آپ را فقط روی SQL Server هم‌نسخه یا جدیدتر از نسخه‌ای که ازش بک‌آپ گرفته شده می‌شود ریستور کرد.)

**۲) نصب وابستگی‌ها:** `pip install -r requirements-mssql.txt`
(به «ODBC Driver 18 for SQL Server» هم نیاز است؛ اگر نصب نیست از سایت مایکروسافت دانلود کنید. Driver 17 هم قابل قبول است.)

**۳) فایل `.env`:** فایل `.env.mssql.example` را کپی کنید به نام `.env` (کنار `manage.py`) و نام سرور را مطابق SSMS بنویسید.
اگر `MSSQL_USER` و `MSSQL_PASSWORD` خالی باشند، «Windows Authentication» استفاده می‌شود.

**۴) تست اتصال و دیدن ساختار دیتابیس (فقط‌خواندنی):**

```powershell
python manage.py describe_db --output schema.txt
```

این دستور جدول‌ها، ستون‌ها، کلیدهای اصلی/خارجی و تعداد ردیف‌ها را چاپ می‌کند و چیزی را تغییر نمی‌دهد.
(با `--samples 3` از هر جدول ۳ ردیف نمونه هم چاپ می‌شود؛ اگر داده‌ی واقعی افراد توی دیتابیس هست قبل از اشتراک‌گذاری مراقب باشید.)

**۵) ساخت جدول‌های جنگو:** `python manage.py migrate`
جدول‌های جنگو (`auth_*`, `django_*`, `accounts_*`, `courses_*`, `blog_*`) **کنار** جدول‌های موجود ساخته می‌شوند و جدول‌های قبلی را تغییر نمی‌دهند.
با این حال قبل از اولین `migrate` از دیتابیس بک‌آپ بگیرید.

> تست‌ها (`python manage.py test`) روی SQL Server یک دیتابیس موقت `test_<نام>` می‌سازند و به دسترسی `CREATE DATABASE` نیاز دارند.
> برای اجرای سریع تست‌ها روی SQLite: `$env:MSSQL_NAME=''; python manage.py test`

## ۵. اجرای تست‌ها

```powershell
python manage.py test
```

تست‌ها (`accounts/tests.py` و `courses/tests.py`) شامل این موارد است: نقش‌ها و ثبت‌نام کاربران، دسترسی هر نقش به هر صفحه،
CRUD دوره و درس، دسترسی به محتوا، ثبت‌نام، جلوگیری از تکراری، ظرفیت، قانون لغو، آزاد شدن ظرفیت، و اعتبارسنجی فرم‌ها.

## ۶. تصمیم‌های طراحی (برای توضیح در ارائه)

- **نقش به‌جای فقط `is_staff`**: مدل `Profile` نقش را صریح نگه می‌دارد؛ با `post_save` برای هر کاربر جدید (از هر راهی ساخته شود) خودکار پروفایل می‌سازد.
- **کنترل دسترسی در سمت سرور**: مخفی کردن دکمه‌ها فقط ظاهری است؛ هر ویو با `role_required` یا `can_manage_course` محافظت شده و تست دارد.
- **عملیات تغییردهنده فقط POST**: ثبت‌نام، لغو، فعال/غیرفعال‌سازی، خروج (محافظت CSRF).
- **غیرفعال‌سازی به‌جای حذف**: حذف دوره، درس‌ها و ثبت‌نام‌ها را هم پاک می‌کند؛ برای همین صفحه‌ی تایید با شمارش داده‌ها دارد و گزینه‌ی غیرفعال‌سازی پیشنهاد می‌شود.
- **slug فارسی**: آدرس دوره از عنوان ساخته می‌شود و با آدرس‌های ثابت (`new`, `manage`, …) تداخل نمی‌کند.

## ۷. استقرار

فایل‌های `Dockerfile` و `docker-compose.yml` (وب + PostgreSQL + nginx) و `liara.json` آماده‌اند.
متغیرهای محیطی در `.env.example` توضیح داده شده‌اند (`SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`, `POSTGRES_*`).

```bash
cp .env.example .env      # مقدارها را پر کنید
docker compose up -d --build
docker compose exec web python manage.py migrate
docker compose exec web python manage.py createsuperuser
```

## ۸. محدودیت‌ها و ایده‌های توسعه

- ثبت‌نام آزاد مدرس: هر کسی می‌تواند هنگام ثبت‌نام نقش «مدرس» انتخاب کند (برای پروژه‌ی آموزشی ساده‌تر است؛ در محیط واقعی بهتر است تایید مدیر داشته باشد).
- ارسال پیامک «مشاوره رایگان» نیاز به API Key کاوه‌نگار در `settings.py` دارد؛ بدون آن فقط در پنل ادمین ذخیره می‌شود.
- امکان‌های بالقوه: آزمون و نمره، ردیابی پیشرفت درس‌ها، گواهی پایان دوره، آپلود فایل برای درس.
